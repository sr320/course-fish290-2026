## Citation format in feedback

In the feedback `.txt`, each improvement bullet must end with a bracketed reference, semicolon-separated when multiple:

```
- The introduction states the hypothesis only in the final paragraph; move it earlier to anchor the reader.  [ref: readings/The Introduction Section.pdf; lectures/290 Week 2a.pdf]
```

Citation rules:

- Every cited file must have been opened with the Read tool in the current session. Citations are evidence the file informed the bullet, not decoration.
- If a bullet cannot be substantively tied to a specific point from one of the rubric-mapped files for that section, either rewrite the bullet to draw on a specific point from the file, or remove the bullet and its citation together.
- Where both a reading and a lecture PDF are mapped to a section, each section of "AREAS FOR IMPROVEMENT" should cite at least one of each.
- If `rubric.md` has been edited since a previous feedback file was written, re-read every rubric-mapped file for sections in the draft from scratch in this session before writing or revising feedback. Tag-swapping without substantive re-grounding is a defect (see SKILL.md "Anti-patterns").
